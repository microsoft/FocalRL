# GPU training setup

FocalRL trains through Miles with Megatron for policy optimization and SGLang for rollout generation.

## Environment and checkpoints

Prepare a Linux environment with compatible PyTorch, Megatron-Core/Megatron-LM, Transformer Engine, SGLang, its router, Ray, Transformers, and the dependencies in `requirements.txt`. Reference versions are Ray 2.47.1, Transformers 5.9.0, Megatron-Core 0.16.0rc0 and SGLang router 0.3.2. Match accelerator-specific PyTorch, attention kernels and patches to your hardware. SGLang must support Qwen3.5, the `qwen3` reasoning parser, and `qwen3_coder` native tool parser.

Install this checkout into the prepared training environment:

```bash
python -m pip install --no-deps -e .
python scripts/launch.py --help
```

Make the same checkout, checkpoint paths, prompt data and Python environment available on every Ray node. Set `PYTHONPATH` to include your Megatron-LM checkout if needed. Convert the selected HF checkpoint with the included `tools/convert_hf_to_torch_dist.py` and matching `scripts/models/qwen3.5-4B.sh` or `qwen3.5-9B.sh`. Prepare both the HF checkpoint and the converted distributed reference checkpoint before launching.

Confirm `python train_async.py --help` and the full SGLang server import succeed in your Linux training environment.

## Services and Ray

Configure the domain services described in [Deep Research](deep_research.md) or [SWE](swe.md), including the external judge. Supply credentials only through the environment or an external secret manager. Do not commit a populated environment file.

Start a Ray cluster with the GPUs allocated for training. The default configuration uses four GPUs for policy optimization and twelve GPUs for rollout generation, with four GPUs per rollout engine on eight-GPU nodes. Policy optimization runs on one node with context parallelism of four. Match the topology flags to your allocation; the launcher checks GPU counts and parallelism settings before launch.

The launcher connects to the existing cluster with `ray.init(address="auto")` and propagates required task/judge settings to workers through Ray's runtime environment. Protect access to that cluster: runtime credentials are available to its workers.

## Preview and launch

Set these path variables to your prepared checkpoints and data:

- `HF_CHECKPOINT`: directory containing the selected HF weights and `config.json`.
- `REF_LOAD`: converted Megatron distributed reference checkpoint directory.
- `PROMPT_DATA`: nonempty JSONL in the domain schema.
- `SAVE_DIR`: a new checkpoint output directory.

```bash
python scripts/launch.py deep_research \
  --hf-checkpoint "$HF_CHECKPOINT" --ref-load "$REF_LOAD" \
  --prompt-data "$PROMPT_DATA" --save "$SAVE_DIR"
```

Replace `deep_research` with `swe` for SWE training. Add `--model-size 9B` for the 9B architecture. Preview checks checkpoint paths and every data record, then prints the training command and configuration. Paths must also resolve on the workers.

After verifying the preview and infrastructure, launch with:

```bash
mkdir -p logs
python scripts/launch.py deep_research \
  --hf-checkpoint "$HF_CHECKPOINT" --ref-load "$REF_LOAD" \
  --prompt-data "$PROMPT_DATA" --save "$SAVE_DIR" \
  --launch > logs/train.log 2>&1 &
TRAIN_PID=$!
printf '%s\n' "$TRAIN_PID" > logs/train.pid
```

**Duration:** cannot be estimated reliably before measuring on the target setup; it depends on GPU hardware, trajectory lengths, judge latency, and the number of groups containing both successful and failed trajectories.

**Progress:** `tail -f logs/train.log`; inspect the Ray dashboard for actor failures and GPU utilization with your accelerator's monitoring command.

**Success:** the training process exits with status zero after completing the configured 80 Deep Research or 40 SWE training iterations and writes a final checkpoint under `SAVE_DIR`.

**Failure/stop:** `kill "$(cat logs/train.pid)"` stops the training process. Inspect Ray and terminate any remaining actors belonging to this job, leaving other jobs on a shared cluster running. Keep the log and complete checkpoints; discard incomplete checkpoint files. The launcher requires a new output directory. To resume, configure Miles' load/resume options with the last complete checkpoint, or restart into a new directory.

## Training configuration

| Setting | Deep Research | SWE |
| --- | ---: | ---: |
| Full rollout groups per batch | 16 | 16 |
| Local rollout groups per batch | 48 | 32 |
| Samples per group | 8 | 8 |
| Maximum local assistant turns | 5 | 20 |
| RL steps | 80 | 40 |
| Maximum context length | 256K tokens | 256K tokens |
| Learning rate | 1e-6 | 1e-6 |

Deep Research starts from an SFT checkpoint; SWE starts directly from the base model. In the paper, Deep Research SFT uses 12K trajectories generated by Qwen3.5-397B-A17B, with three epochs, a learning rate of 1e-5, and batch size 128.

Full trajectories and local continuations jointly optimize the policy. Advantages are computed by subtracting the mean reward within each rollout group, and the policy loss is averaged over generated tokens. Local rewards evaluate two criteria: whether the continuation avoids the identified error and whether it makes the specified correction. A continuation receives 0 if it fails to avoid the error, 0.5 if it avoids the error but does not make the correction, and 1 if it satisfies both criteria.

Full rollouts use a 200-turn interaction limit and a 256K-token context window for both tasks. Local continuations are limited to 5 turns for Deep Research and 20 turns for SWE. Deep Research reserves 32,768 tokens of context capacity for generating the final answer. Limits on individual model responses are configured separately from the total context length.

Configure hardware-specific flags for your cluster topology and accelerator stack.
